Verbatim copies of the Claude Design project files, kept in the repo so the design is
retrievable without a claude.ai session. **Reference only — nothing in this folder is
compiled.** It lives under `docs/` deliberately: the Xcode target uses a synchronized root
group, so anything under `escape_plan/` would be built.

## The 2D house — and why the app does not use it

The design draws the home as a **2D floor-plan illustration** (rooms as rectangles, routes as
dashed cool-blue paths with numbered stops, hazard as a warm radial). That 2D drawing is
preserved here in `Escape Plan.dc.html` for anyone who wants to lift it later.

The shipping House tab stays on the **3D SceneKit dollhouse** (`escape_plan/Renderer/`). That
was the explicit call when this design was implemented: keep the house 3D, keep the 2D code
somewhere retrievable. To retrieve it, search this file for the House artboard's SVG/markup;
the route/exit/hazard colour rules it uses are the same ones `DollhousePalette` and
`Theme` already enforce (cool = route, warm = hazard).

## Re-importing or re-syncing

- With a working `/design-login`, the `DesignSync` tool reads the project directly:
  `list_files` / `get_file` against the project id above.
- Without it, open the project URL in a signed-in browser; the page's own RPC
  (`POST /design/anthropic.omelette.api.v1alpha.OmeletteService/GetFile`,
  JSON `{"projectId","path"}`, header `Connect-Protocol-Version: 1`) returns
  `{"content": <base64>}`. That is how this export was produced.
