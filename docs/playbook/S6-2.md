S6.2 — Corpus: earthquake and severe-weather grounding · ~6h · Prereqs: none (blocks S6.3, S6.4)

Context: the pivot doubles the app's safety surface, and the project's hardest rule is that the AI
may only ever say what the corpus says, with a citation that resolves. Today `backend/corpus/`
knows about fire and nothing else. Every earthquake and tornado claim the S6.3 engine, the S6.4
checklist and the S6.7 score will make has to be sourced first — so this session comes before any
of them. It is entirely offline research and writing; it touches no app code and no schema.

---

```
Read CLAUDE.md, docs/playbook/06-pivot-intro.md, and .claude/rules/paths/corpus.md before starting.
Then read backend/corpus/escape-planning-nfpa.md and backend/corpus/special-considerations.md to
absorb the house voice — you are matching an established style, not inventing one.

MISSION
Extend backend/corpus/ to ground two new perils — earthquake and severe weather (tornado) — to the
same evidentiary standard the fire corpus already meets, so the deterministic engine and checklist
built on top of it can cite real sources for every claim.

THE STANDARD (non-negotiable, from rules/paths/corpus.md)
- Every content file is markdown with YAML front-matter: source org, doc title, URL, retrieved
  date, topic tags.
- Every claim carries an inline [cite: source-id] tag, and every id resolves in sources.json.
- Paraphrase and structure; do not paste long verbatim passages. Keep citations exact.
- NEVER add safety guidance without a real, named source. No source → it does not go in.
- Compilation docs (which synthesize across sources) get a non-source primary id and only ever
  cite underlying external sources.

WHAT TO WRITE

1. backend/corpus/earthquake-preparedness.md — sourced from USGS, FEMA, and the Great ShakeOut
   (earthquakecountry.org / ShakeOut drill guidance). It must cover, because downstream sessions
   depend on each:
   - Drop, Cover, Hold On as the primary protective action, and specifically WHAT counts as cover
     (a sturdy table/desk) and what does not. S6.3 searches the model for this.
   - The "triangle of life" is discredited — say so with a citation. If the engine ever proposes
     standing next to furniture instead of under it, this is the line that stops it.
   - Securing tall/heavy furniture, water heaters, and what a renter can do without altering the
     structure (S6.4 needs a renter-safe variant that is sourced, not improvised).
   - Gas shutoff guidance — critically, the mainstream guidance that you shut gas off ONLY if you
     smell/hear a leak, and that you do not turn it back on yourself. Do not let the checklist
     tell people to routinely shut off their gas.
   - Post-shaking evacuation: when to leave, aftershock caution.

2. backend/corpus/severe-weather-tornado.md — sourced from NOAA/NWS, FEMA, and the Red Cross.
   Must cover:
   - The safe-location rule the S6.3 search implements: lowest floor, most interior room, as many
     walls as possible between you and the outside, away from windows. Cite it precisely — this is
     the exact inverse of fire's "get to the exterior," and the engine's objective function will be
     justified by this line.
   - Why a basement/storm shelter beats an interior bathroom/closet, and what to do when neither
     exists (including the mobile-home case: leave for a sturdy building, because no interior room
     in a mobile home qualifies — S6.3 needs this to justify a no_viable_safe_room finding).
   - Watch vs. warning, and alert reception (NOAA weather radio, phone alerts) — which is where the
     hearing_impaired tag from S6.1 finally earns its checklist item.
   - Protecting your head/neck; getting under something sturdy.

3. backend/corpus/sources.json — add every new source with the same field shape the existing 11
   use. Real orgs, real titles, real URLs, real retrieved dates. Do not invent a URL you have not
   confirmed, and do not cite a page you did not read.

4. Thresholds — if and only if you find genuinely numeric, codified thresholds worth computing on
   (they are much rarer here than in fire's egress-window case), add them alongside
   egress_thresholds.json following the same imperial-as-codified + metric-authoritative pattern.
   If you find none, say so explicitly in the session note. Do NOT manufacture numbers to make the
   engine's job easier — S6.3 is expected to work from geometry plus qualitative rules, and
   docs/profile-constraint-mappings.md already sets the precedent for honestly labelling an
   engineering constant as an engineering constant rather than dressing it as a safety threshold.

5. Update backend/corpus/fire-facts-stats.md ONLY if you add cross-peril framing to it. It is a
   compilation doc; keep its non-source primary id discipline.

VALIDATION
`python3 backend/corpus/validate.py` must exit 0. It checks source resolution, front-matter, cite
tags, and imperial↔metric consistency (1% tolerance). It is stdlib-only by design — keep it that
way. If your additions need a new validation rule (e.g. a new thresholds file), extend validate.py
rather than loosening it.

ACCEPTANCE
- validate.py exits 0, and reports the new file and source counts.
- Every claim in both new files carries a resolving [cite: ...].
- A spot-check of five random citations confirms the cited source actually says that.
- The grounding-auditor agent run over backend/corpus/ finds no uncited claims and no invented
  guidance.
- No app code, schema, or engine file changed in this session — this is corpus-only.

CLOSE OUT
Update docs/tracker/TODO.md (S6.2 done, unblocks S6.3/S6.4), write docs/tracker/notes/<date>-s6-2-corpus-perils.md,
add any new source org to docs/tools-used.md if that file tracks data sources, and record in
docs/decisions.md any place you deliberately declined to add guidance for lack of a source — that
list is as valuable as what you did add.
```
