# S11.32: Sync handles a stale revision and a full account · ~3h · Lane D (iOS) · Prereqs: S11.22, S11.30 merged AND deployed

Context: after S11.30, the server can refuse a stale update (409 with the current revision) and a full account (a
quota status). The app does not yet send `base_revision`, so it still gets the old last-write-wins behaviour, and it
has no handling for either refusal: a quota error would be retried on every sync, forever. Sending the new field to a
server without S11.30 returns 422 (the request model forbids extra fields), which is why S11.30 must be deployed first.
