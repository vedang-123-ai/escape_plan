### Four traps, each already paid for once

1. **"Attach the JWT to all requests" (WHAT TO ADD #1) is wrong as written.** `/routes`,
   `/score`, `/chat` and friends are guarded by the shared `BACKEND_BEARER_TOKEN`; the cloud
   routes use a per-user JWT. They are **different axes** and `backend/app/api_auth.py`
   deliberately does not layer them. Attach the JWT to **`/homes` only**. Mixing them would work
   today and break the moment that comment stops being true.

2. **A home that has been through the server differs BY BYTES but not BY VALUE.** pydantic
   serialises absent optionals as explicit `null` and fills `objects: []` — measured, 21 extra
   keys on `bungalow.json`. Swift decodes it to an **equal** `HomeModel`. So compare **decoded
   models** or `revision`, **never encoded JSON**: a dirty-check on bytes marks every synced home
   permanently modified.

3. **Sync state goes in a SIDECAR file, not in `HomeModel`.** Adding a `last_synced_revision`
   field to the model is a **schema change** — `schema_version` bump, pydantic, Swift Codable,
   and a clean `schema-contract-guardian` run, per the one law in `CLAUDE.md`. Nothing in
   `Persistence/` tracks sync state today; check before assuming.

4. **`HomeModelStore` is 702 lines and is the ONLY mutation path**, with undo/redo and autosave
   hanging off it. Sync writing into it is where the bugs will be. Treat it as the risky step.
