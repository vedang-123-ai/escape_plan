S6.8 — Earthquake and severe-weather drill modes · ~6h · Prereqs: S6.3

Context: the strongest argument for this app is not that it tells you something you did not know —
it is that a practiced action beats a known fact under stress. Fire drill mode already exists
(S4.2). This session gives earthquake and tornado the same treatment, which is what makes the
"three perils" claim real to a user rather than a feature-list item.

---

```
Read CLAUDE.md, docs/playbook/06-pivot-intro.md, and .claude/rules/languages/swift.md.
Then read escape_plan/DrillMode/DrillScreen.swift, DrillSession.swift, DrillInstructions.swift and
DrillCitedText.swift — you are extending an established pattern, including its citation discipline.

MISSION
Add two drill modes alongside the existing fire drill: an earthquake Drop-Cover-Hold drill and a
severe-weather safe-room drill, both driven by S6.3's engine output and both citing the corpus.

EARTHQUAKE DRILL — Drop, Cover, Hold On
- Per room, use S6.3's cover-point output: "you are in the kitchen — get under the table, now."
- Timed sequence with the three phases, each with the corpus-cited instruction text.
- Rooms with no qualifying cover show the honest finding S6.3 produced, not an improvised
  alternative. If the corpus supports a fallback (drop beside an interior wall away from windows),
  use its exact guidance with its citation; if it does not, say there is no good cover in this room
  and make that a mitigation item rather than inventing advice.
- NEVER render the "triangle of life" (stand beside furniture, not under it). It is discredited and
  the S6.2 corpus says so explicitly. Add a test asserting no drill string ever instructs it.
- Aftershock beat: the drill does not end when shaking stops — it ends with the post-shaking
  evacuation, which reuses the fire route. That transition is the moment that shows the engine
  reasoning about two perils in sequence, so make it legible.

SEVERE-WEATHER DRILL — get to the safe room
- Route the selected person from their origin to S6.3's computed safe room, under their own
  constraints, with a target time.
- The contrast with the fire drill is the whole point and should be impossible to miss: same house,
  same person, opposite direction. If a judge runs both back to back, that comparison is the demo.
- When the engine returned no_viable_safe_room, the drill must NOT run a least-bad substitute. Show
  the finding and the corpus's actual guidance (for the mobile-home case: leave for a sturdy
  building). A drill that rehearses a bad shelter is worse than no drill.

SHARED REQUIREMENTS
- Every instruction string carries a resolving corpus citation, following DrillCitedText's existing
  pattern. No uncited safety instruction ships.
- Per-profile: a mobility_limited person's drill respects avoid_stairs in every mode.
- Haptics at phase transitions (the simulator cannot verify a single one — this needs a device).
- Drill completion feeds the S6.4 practice items and their recurrence interval.
- Theme.swift semantic scale only, no new colours, route orange reserved for lit routes and exits.
- VoiceOver: every phase announces; the drill must be completable without sight, which matters
  literally for a vision_impaired profile.

ACCEPTANCE
- All three drills runnable back to back on twostory.json, with fire and tornado visibly routing
  the same person in different directions.
- A room with no cover object produces the honest finding, not a fabricated instruction.
- A no_viable_safe_room home refuses to run the tornado drill and explains why.
- Every drill string's citation resolves against backend/corpus/sources.json (test this over the
  whole string set, not by spot check).
- Haptics verified BY HAND on a physical iPhone — note in the session note that you did it; the
  simulator cannot.
- xcodebuild test green (re-run a red once before believing it).
- grounding-auditor agent over the new drill text; swift-scenekit-reviewer over the new Swift.

CLOSE OUT
docs/tracker/TODO.md, session note (including the device haptics confirmation), docs/decisions.md
for any drill-pacing constant you introduced — and label those constants as engineering choices,
not corpus values, the way the rest of this repo does.
```
