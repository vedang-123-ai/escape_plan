S6.9 — The responder snapshot: opt-in, anonymous, manual · ~5h · Prereqs: S6.1, S6.3

Context: the pivot's most quotable claim is that a scanned home could tell an arriving crew what
they cannot know — where the shutoffs are, which bedroom holds someone who cannot self-evacuate,
where the exits are. This session builds that artefact honestly and stops exactly where the honesty
stops: there is no fire department on the other end, and the app must never imply there is.

---

```
Read CLAUDE.md, docs/playbook/06-pivot-intro.md, and .claude/rules/global/conventions.md.
Then read escape_plan/Screens/SettingsScreen.swift, escape_plan/Persistence/, and
escape_plan/Export/ShareSheet.swift.

MISSION
Build an opt-in, anonymous, user-initiated "responder snapshot" export: a single shareable artefact
summarizing what a first responder would want to know about this home before entering it.

DO NOT REBUILD THE PDF PIPELINE
escape_plan/Export/ already renders a printable per-floor plan and you are re-targeting it, not
writing a second one: EscapePlanPDF.swift (one page per floor via UIGraphicsPDFRenderer),
FloorPlanDrawing.swift (top-down 2D floor drawn with Core Graphics straight from the schema
polygons), PlanProjection.swift (metres → page points), PlanInk.swift (the greyscale encoding
table), PDFText.swift (text into a raw CGContext, with measure-then-place overflow helpers) and
EscapePlanExporter.swift (assembles from disk, writes a share-ready file). RouteNarration.swift is
likewise pure Foundation and already turns engine waypoints into ordered plain-English steps — it
is documented as having two callers by design, and this snapshot is a third. Extend these; a
parallel renderer would drift from the printed plan it is supposed to match.

THE SCOPE LINE — DO NOT CROSS IT
This is DESIGNED AND DEMOABLE, NOT INTEGRATED. Locked at scoping time:
- No backend endpoint. No upload. No account. No partner department. No auto-transmission of any
  kind, ever, under any setting.
- The user is always the one who hits share. The app generates a file; the human hands it over.
- The project's local-only, anonymous, no-accounts architecture survives this session intact. If
  you find yourself designing a sync path, stop — you are building the wrong session.
- The UI must not claim or imply that any department receives this. Copy like "shared with your
  local fire department" is false and must not ship. "Generate a snapshot you can give to your
  local fire department" is true.

WHAT THE SNAPSHOT CONTAINS
- Floor plan per floor, exits marked, from the existing renderer.
- Utility shutoff locations (S6.1 safety points) — the single most operationally useful item.
- Count and room-location of occupants who cannot self-evacuate (from mobility_limited /
  vision_impaired profiles), expressed WITHOUT names: "1 occupant needing assistance — Master
  Bedroom, floor 2." Anonymity is the point; a named list is a different, much more sensitive
  artefact and is out of scope.
- The computed storm safe room, and any no_viable_route / no_viable_safe_room findings — a crew
  benefits from knowing the upstairs bedroom has no accessible way out.
- Composite readiness score (S6.7) if present.
- Generation timestamp and `meta.last_scanned`, prominently. A stale plan presented as current is
  the one way this artefact could actively mislead someone making entry decisions.

FORMAT
Two outputs from one generator: a human-readable PDF (what a crew or an insurer would actually
look at) and a machine-readable JSON (what a future integration would consume). Share via the
existing ShareSheet — AirDrop, Files, print, Messages. A QR code linking to nothing external is
NOT acceptable; if you want a QR affordance it must encode the payload itself or be left out.

CONSENT UX
- Lives in Settings. Default OFF. Opt-in, never opt-out.
- Before the first generation, a plain-language screen: exactly what is included, exactly what is
  excluded (names, address unless the user added one, anything identifying), and the fact that
  nothing is transmitted automatically. Written for a person, not a lawyer.
- The user can regenerate any time; each generation is a fresh snapshot, not a living document.
- Turning the toggle off deletes any cached snapshot from disk.

PRIVACY REVIEW
Treat this as the highest-sensitivity surface in the app: it is a map of a home, including where
vulnerable people sleep. Before you ship it, walk through what happens if the file leaks — and make
sure the answer is "it contains no names, no address the user did not type, and no device id."
Run the /security-review skill over the generator and the persistence path. (There is no
`security-reviewer` agent in .claude/agents/ — the six that exist are doc-auditor,
grounding-auditor, lane-integrator, schema-contract-guardian, session-auditor and
swift-scenekit-reviewer.)

ACCEPTANCE
- Toggle off (default): no snapshot exists on disk, and nothing can generate one.
- Toggle on → consent screen → generate → PDF and JSON both produced, openable, and correct against
  twostory.json.
- The occupant-assistance line contains no names anywhere in either output (assert this in a test
  over the generated bytes, not by eye).
- A home with `last_scanned` null or stale renders that fact prominently on the artefact.
- Nothing in the app makes a network call as a result of this feature — verify with the network
  inspector, not by reading the code.
- Toggling off removes the cached artefact.
- xcodebuild test green (re-run a red once).

CLOSE OUT
docs/tracker/TODO.md, session note, and a docs/decisions.md entry stating plainly that the responder
and insurance stories are designed-not-integrated, what would be required to make them real
(a receiving partner, a transport, a consent-revocation story), and that no future session should
quietly turn this into an upload without revisiting the accounts/sync scope lock.
```
