# S11.27: AI spend has a ceiling that nobody outside the server can reset · ~4h · Lane E (backend) · Prereqs: S11.14 (blocks S11.28, S11.29, S11.39)

Context: every compute and AI endpoint is protected by one shared bearer token, and that token ships in plain JSON
inside every app build. Anyone with the app, or its IPA, has it. The AI cost guard keys its per-client bucket on the
first `X-Forwarded-For` value, which the caller sets, so a script gets a fresh bucket per request; the global semaphore
caps concurrency (4), not spend. Four `/build` loops of up to 40 model calls each can run all day. `/score?include_recommendations=true`
calls the AI outside the guard entirely (AUD-006, already on BLOCKERS). The Anthropic account has run dry once already.
The token itself is not the control and cannot be made one before the deadline, so spend needs a ceiling the client
cannot reset. `require_token` is also duplicated in two files (AUD-043), which this change would otherwise have to edit twice.
