S6.5 — The household interview (iOS onboarding) · ~7h · Prereqs: S6.1 (blocks S6.6)

Context: the first thing a judge will see. Today first launch seeds a demo home; after this session
it opens a warm, conversational interview that learns who lives here and what they need, then hands
those facts to the deterministic rule table. The whole pivot's credibility rests on this feeling
like a conversation while being, underneath, a fixed branching form producing clean structured data.

```
Read CLAUDE.md, docs/playbook/06-pivot-intro.md, and .claude/rules/languages/swift.md.
Then read escape_plan/Onboarding/OnboardingFlowView.swift, escape_plan/ContentView.swift,
escape_plan/Screens/ProfileEditorView.swift and the HomeModelStore reducer before writing anything.

MISSION
Replace the S4.1 demo-seed onboarding with a five-step household interview that produces Profile
objects and the schema-2.0 `household` facts, conversationally narrated, fully skippable, and
editable later.

THE ONE ARCHITECTURAL POINT THAT MATTERS
This is a FIXED, BRANCHING WIZARD with warm scripted copy. It is NOT a free-form chat with an LLM.
Two consequences, both deliberate:
- The output is always clean structured data — no probabilistic extraction, nothing to validate
  after the fact, and no way for the AI to invent a household fact.
- IT MUST WORK WITH ZERO NETWORK CALLS. The Anthropic account is currently out of credits and
  /explain, /analyze and /chat all return 502. If the app's new front door needs a live model call
  to get past screen one, the app is dead on first launch. Ship the narration as static copy.
  (A later polish session may add per-household phrasing on top; it must degrade to this copy.)

THE FIVE STEPS
0. Welcome — one screen of framing: "I'll ask a few questions about your household, then build you
   a personalized readiness checklist for fire, earthquake and severe weather." One CTA.
1. Who lives here — add-person cards: name (optional), age. Bucket age into the existing child /
   elderly tags; do not store a birthdate you do not need.
2. Per-person needs — for each person: mobility limitation, hearing, vision toggles. This is the
   sensitive screen. All toggles default OFF, nothing is required, no justification is ever asked
   for, and the copy must not imply the person is a problem to be solved. Write it the way you
   would want to be asked about your own grandmother.
3. Rent or own — one household toggle. The copy should say why it is asked (some safety fixes need
   a landlord's permission), because an unexplained tenure question reads as data harvesting.
4. Existing equipment — multi-select: smoke alarms, CO detector, fire extinguisher, generator.
   Framed as "so we don't tell you to buy what you already own."
Then: "Building your plan…" → the deterministic rule table runs → land on the Home tab.

SKIP AND EDIT (locked decisions)
- Every question is skippable with a visible affordance. A skipped question produces the
  unconstrained default — exactly what an untagged profile does today. Skipping must never produce
  a worse-than-nothing state or a half-written profile.
- The entire household profile is editable later from Settings, field by field — not "redo the
  interview." Someone has a baby, a parent moves in, a kid moves out; none of those should require
  starting over.

DATA FLOW
- All mutations go through the single HomeModelStore reducer. Do not mutate the model from views —
  undo/redo and autosave depend on this and the Swift rules are explicit about it.
- The interview writes: `profiles[]` (with tags) and `household` (tenure, existing_equipment).
- Persistence stays local JSON documents. No accounts, no sync, no upload. Nothing the user types
  here leaves the device.
- Keep the @AppStorage("onboarding.completed") gate pattern so the flow never reappears on its own,
  but make sure "completed" cannot be set by a crash mid-flow leaving an empty household.

WHAT HAPPENS TO THE OLD FLOW
The S4.1 demo-home seed is still useful for demos and for anyone who wants to look around before
scanning. Keep it reachable — offer it as an explicit "just show me an example home" escape hatch
at the end of the interview, not as the default path. Do not delete it.

UI QUALITY BAR
Stay inside Theme.swift's semantic scale. Do NOT introduce new colours, and do NOT use route orange
in chrome — it is reserved for lit routes and exits. Advisory chrome uses dark amber. Support
Dynamic Type, VoiceOver labels on every control, and both orientations.

ACCEPTANCE
- Fresh install → interview → a real household exists in the model, verified by reading the saved
  JSON document, not by trusting the UI.
- Skipping every single question still produces a valid, loadable home document with an
  unconstrained default profile.
- Airplane mode: the entire interview completes with no network access and no error banner.
- Editing a person in Settings afterwards updates the model through the reducer, and undo works.
- VoiceOver: every step is navigable and every toggle announces its state.
- xcodebuild test green (re-run before believing a red; true counts via
  `xcrun xcresulttool get test-results summary --path <bundle>`).
- Run the swift-scenekit-reviewer agent over the new Swift.

CLOSE OUT
Update docs/tracker/TODO.md, write the session note, and record in docs/decisions.md the ruling that
the interview is scripted rather than model-generated, with the outage reasoning — that is exactly
the kind of decision a future session will otherwise try to "improve."
```
