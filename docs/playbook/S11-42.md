# S11.42: Server settings: a token rotation reaches every install, and bad addresses are refused · ~2h · Lane D (iOS) · Prereqs: S11.14 (owner answered the AUD-001 rotation and "Advanced in Release" questions)

Context: once the app assigns `apiClient.bearerToken`, which any "Save changes" tap does even when only the URL was
edited, the value in UserDefaults wins over the bundled one on every later launch. So when the owner fixes the known
token mismatch (AUD-001) by rotating the token and shipping a new build, every tester who ever tapped Save keeps the old
token and gets 401 everywhere, told to "check it in Settings". `save()` also accepts any string URL(string:) parses,
including the field's own placeholder `api.example.com` (no scheme), which breaks every request, and "Saved" shows
regardless. The Advanced section ships in Release builds.
