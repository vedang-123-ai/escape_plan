# S11.30: Cloud homes get a per-user quota and compare-and-set revisions · ~3h · Lane E (backend) · Prereqs: S11.26, S11.28 (api_auth.py serial) (blocks S11.32; must be DEPLOYED before S11.32 ships)

Context: `POST /homes` reads the stored revision, adds one, and upserts unconditionally. The request carries no "based
on revision N". Two devices that both last synced revision 5 and both push an edit both write revision 6; the second
wins. The first device then records itself as synced at 6 and never pulls the other version. That breaks the per-write
monotonic revision the whole SyncReconciler model assumes. Separately, any registered account (registration is open)
can store unlimited homes of unlimited size in a 512 MB free Atlas cluster; one script fills it and every user's sync
then fails (AUD-007).
