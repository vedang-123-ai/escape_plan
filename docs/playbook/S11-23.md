# S11.23: A score belongs to the home it was asked for · ~2h · Lane D (iOS) · Prereqs: S11.17 (same file; blocks S11.35, S11.37)

Context: `ReadinessStore.fetchScore` captures the active home, awaits `/score`, and then writes `breakdown`
unconditionally. `load` is called from several uncancelled tasks: launch, `select`, onboarding completion, and the sync
`onChange`. On a cold Render start (51 s measured), a user who switches from home A to home B can get A's late response
after B's, and then sees A's score and checklist under B's name. Ticking one of those items saves A's item ids into B's
checklist state. `ScoreBreakdown` carries no home id, so nothing downstream can detect the mix-up. `isScoring` has the
same problem: the first request to finish clears it while another is still running.
