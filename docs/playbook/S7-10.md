S7.10 — OPTIONAL: Vision suggestions into the editor · ~5h · Prereqs: S7.9 (first to cut)

Context: S7.9 ends with a confirmed suggestion ("yes, that's a space heater") and deliberately
writes nothing. This session closes the loop: a confirmed suggestion becomes a pre-filled
hazard-hunt step — the right category selected, the right follow-up question asked ("is it
strapped?") — and the user places the object with the editing tools that already exist. The
photo never supplies geometry, because it has none to give: no dimensions, no position, no
elevation. Everything metric comes from the user's placement or a scan. If S7.9 returned
NO-GO, this session was already cut and this file is a record of what would have been.

---

```
Read CLAUDE.md, docs/playbook/07-object-hazard-intro.md, docs/object-hazard-spec.md §6, the
S7.9 session note (the label mapping and verdict), and the S7.6 hazard-hunt flow before
writing anything.

MISSION
Wire confirmed Vision suggestions into the hazard hunt: suggestion → pre-filled hunt step →
user places/confirms → ordinary FloorObject via the ordinary reducer actions. No new model
pathways, no new mutation surface.

WHAT TO BUILD
1. Suggestion → hunt-step mapping: each GO class from S7.9 maps to the hunt step S7.6
   already defined for it (space heater → heat_source placement step; water heater →
   water_heater + secured question; bookcase → bookcase + secured question; mounted TV /
   mirror → mounted object + elevation step). The mapping is a small table, tested, and
   refuses unknown classes loudly in debug rather than guessing.
2. Placement flow: the pre-filled step drops the object at the current room's centroid
   with the category's default dimensions (defaults live with the category definitions,
   one place), then hands the user the existing drag/resize/rotate tools. Copy makes the
   division of labor plain: "the photo suggested it — you place it."
3. Provenance: objects created this way are source: "manual" (a human confirmed and placed
   them — the photo was advice, not a sensor measurement). Record the ruling in
   decisions.md; if you rule otherwise, the schema's source enum is S7.1 territory and the
   contract-cost decision reopens, so don't.
4. The suggestion is dismissible at every step, and dismissal leaves zero residue in the
   model or the hunt's resume state.

DELIBERATELY NOT IN THIS SESSION
- No batch/multi-object flows — one photo, one suggestion, one placement.
- No confidence thresholds tuning beyond what S7.9 shipped — if the suggestions feel
  wrong, the fix is S7.9's mapping table, not new UI logic here.
- No engine, checklist, or backend changes of any kind — a placed object flows through
  S7.4/S7.5 like any hand-added one, which is the whole point.

ACCEPTANCE
- `swift test --package-path tools/editorcore` green with tests: each GO class maps to
  its step; unknown class refused; the created object carries the right category,
  source: "manual", and no confidence field; dismissal leaves no residue.
- iOS unit tests green per standing rules (owner-approved runs only).
- End-to-end on simulator or device (owner-coordinated): photo → suggestion → confirm →
  place → the object appears in the 3D view, and a subsequent /score reflects the new
  hazard finding (e.g. the placed heater near a sofa yields the heat_clearance item) —
  proving the loop closes into the deterministic engine with zero special-casing.
- Round-trip: a document containing a photo-suggested object validates as 2.1 and
  round-trips like any other.
- Run the swift-scenekit-reviewer agent and act on what it finds.

CLOSE OUT
Update docs/tracker/TODO.md (S7.10 done or CUT per the charter's order — it is first in
line), write docs/tracker/notes/<date>-s7-10-vision-editor.md from _TEMPLATE.md, and add a
docs/decisions.md entry for the source:"manual" provenance ruling and the per-category
default dimensions.
```
