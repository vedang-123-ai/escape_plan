S7.8 — STRETCH: the exit-path re-check · ~6h · Prereqs: S7.3, S7.4 (cut before any core session)

Context: the spec's honesty section admits the one thing scan-based detection cannot do: a
backpack dropped in the hallway tonight. A stored model is a photograph of the past. The honest
version of "clutter detection" is a diff: re-scan just the corridor, compare against the stored
model, and say "something new is in your escape path" — without pretending to know what it is.
This is the arc's most novel demo moment and its most cuttable session: everything else works
without it, which is exactly why it sits behind S7.3 and S7.4 and carries a CUT FIRST label
(after the optional Vision pair). Scope discipline matters more here than anywhere: this is a
diff feature, not SLAM research.

---

```
Read CLAUDE.md, docs/playbook/07-object-hazard-intro.md, docs/object-hazard-spec.md §2 (the
transient-clutter policy this implements), backend/app/convert/ (what a partial scan converts
to), backend/app/routing/obstructions.py, escape_plan/Capture/ (the capture flow you are
adding a mode to), and scoring/checklist.py's recurrence mechanics before writing anything.

MISSION
A "re-check my exit path" flow: single-room RoomPlan capture of a corridor/room on the primary
route → convert → geometric diff against the stored model's same room → if a new object
intrudes on the route corridor or an opening approach, say so — measured, cited ("keep exits
clear" sources already exist), and without claiming to know what the object is.

SCOPE FENCES (this is the whole design)
1. Diff by GEOMETRY, not identity: new-scan objects (and, if cheap, wall-anomaly blobs the
   converter already surfaces) whose footprint does not match any stored object within a
   registration tolerance — an ENGINEERING CONSTANT in object_hazard_thresholds.json,
   honest about RoomPlan's re-scan registration error, which you must measure on synthetic
   pairs before picking it.
2. Room matching is explicit, not inferred: the user launches the re-check FROM a room
   ("re-check the hallway"), so the diff knows its target room a priori. No global
   re-registration of the whole home. If the scanned geometry cannot be matched to that
   room's polygon within tolerance, the honest output is "couldn't line this scan up" —
   a failure state, not a guess.
3. Output is the existing machinery: run the obstruction probe (and R1's door-approach
   check) on the stored model WITH the diffed objects injected as source:"scan",
   low-confidence, category "other" objects. New findings relative to the stored model are
   the answer — rendered through existing finding UI, worded as "something new" (never a
   guessed category). The user can promote a diff object into the model via the editor or
   dismiss it; dismissal discards it (a backpack is not architecture).
4. The recurring "walk your exit path" checklist item (recurrence_days mechanics already
   exist) gains a "re-check with the camera" affordance — the feature's front door lives
   on an item users already see.

DELIBERATELY NOT IN THIS SESSION
- No object classification of diffed blobs. "Something new" is the claim; more is a lie.
- No persistent storage of re-check scans — the result is a moment-in-time advisory;
  persisting it would recreate the stale-timeline problem the evacuation cache decision
  already documents.
- No multi-room sweeps, no whole-home re-registration, no background monitoring.

ACCEPTANCE
- `backend/.venv/bin/python -m pytest backend/tests/ -m "not live"` green with diff tests
  on synthetic pairs: identical scans → zero diffs (the registration tolerance holds);
  a planted new box in the corridor → exactly one diff object → obstruction finding names
  it; the same box outside the route corridor → diff recorded, no route finding.
- Mismatched-room scan → the explicit couldn't-line-up failure, never a silent wrong answer.
- `swift test --package-path tools/editorcore` green; iOS per standing rules.
- One hardware run (owner-coordinated, can ride the S7.7 field trip): re-check a real
  corridor twice — once clear, once with a real object planted — and record both outcomes
  with evidence in docs/evidence/.
- Wording audit: every user-facing string says "something new" or equivalent; grep the diff
  path for category names in copy and remove them.
- Run the grounding-auditor agent (cited "keep exits clear" wording; no invented claims)
  and act on what it finds.

CLOSE OUT
Update docs/tracker/TODO.md (S7.8 done or explicitly CUT with the cut recorded), write
docs/tracker/notes/<date>-s7-8-exit-path-recheck.md from _TEMPLATE.md, and add a
docs/decisions.md entry: the registration tolerance measured and chosen, the dismissal
semantics, and — if cut — that the cut happened per the charter's order.
```
