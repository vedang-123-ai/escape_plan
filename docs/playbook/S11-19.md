# S11.19: The House editor reloads when its home changes underneath it · ~5h · Lane D (iOS) · Prereqs: S11.18 (blocks S11.20, S11.21, S11.22, S11.24)

Context: this is the audit's most serious data-integrity bug. `HouseScreen`'s editor session loads the home once
(`loadIfNeeded` returns early when a session exists), and the TabView keeps that session alive across tab switches.
Other writers change the same `Documents/Homes/<id>.homeplan.json` without telling it: the re-scan "Add to Home",
the onboarding interview, sync pulls, and soon Profiles (S11.20) and delete (S11.21). House's next edit autosaves its
stale model over their work. Worse, `onDisappear` clears `library.editor` and `syncRepository.openHomeID` and nothing
sets them again on re-appear. So a sync can pull another device's newer copy while House is visible; the next edit
overwrites it, and the next sync pushes the stale version to the server. Every later iOS session adds a writer, so this
lands first.
