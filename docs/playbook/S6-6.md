S6.6 — The checklist becomes the Home tab · ~8h · Prereqs: S6.4, S6.5

Context: the session where the pivot becomes visible. Today Home is a saved-homes list and the
checklist is buried inside the score screen. After this, the checklist IS the app's front page —
the thing a user opens, works through, and returns to. This is also the session most likely to be
judged on craft rather than correctness, so budget time for the states, not just the happy path.

---

```
Read CLAUDE.md, docs/playbook/06-pivot-intro.md, and .claude/rules/languages/swift.md.
Then read escape_plan/Screens/HomeScreen.swift, escape_plan/Screens/ScoreScreen.swift (it already
renders the checklist — study how), escape_plan/Screens/Theme.swift, and ContentView.swift.

MISSION
Promote the readiness checklist to the Home tab: one unified, hazard-tagged, sectioned list that
deep-links into the screens that do the actual work, with a progress header, honest states, and a
rescan nudge.

DO NOT REBUILD WHAT EXISTS
ScoreScreen.swift already renders checklist items with toggles, backed by ChecklistStateStore and
re-POSTing /score. Lift and extend that machinery; do not write a second checklist renderer. When
you are done there should be ONE checklist implementation, used in the Home tab, with ScoreScreen
either linking to it or showing only the score breakdown.

LAYOUT
- Header: composite readiness ring (S6.7 owns the number; if S6.7 has not landed yet, render the
  existing single score and leave the breakdown wiring behind a clearly-marked seam).
- Sections, in dependency order: Foundation → Know your home → Practice → Mitigate → Stay ready.
- Each row: title, a hazard chip (Fire / Earthquake / Severe Weather / General), and the one-line
  corpus-cited "why" from S6.4. The why-line is what makes this app feel like it knows something
  rather than nagging.
- Rows deep-link to the screen that completes them: scan → the RoomPlan flow; routes → HouseScreen;
  drills → DrillScreen; shutoffs → the editor's placement tool. A row that cannot be completed
  in-app says what to do in the physical world instead of pretending to be tappable.

STATE DISCIPLINE (this is the part that goes wrong)
- Derive done-ness from the model wherever a spatial artefact exists: a gas shutoff placed in the
  model means that item is DONE — the user must never have to both do the thing and tick the box.
- Store completion only for narrative items with no artefact (drills practiced, kit assembled).
- Blocked items (need a house model first) render as visibly blocked with the reason, not hidden
  and not tappable-into-nothing. A dead tap is the single worst thing this screen can do.
- High-severity findings from the engine (no_viable_route, no_viable_safe_room) pin to the top and
  are visually distinct from ordinary to-dos. These are the product's most valuable output; they
  must not sit ninth in a list of chores.

THE RESCAN NUDGE
Driven by `meta.last_scanned` from S6.1 and the ~6-month engineering-choice interval from S6.4.
When stale: a non-blocking banner in the Stay-ready section, dismissible, never a modal, and it
does NOT block or reduce the score. A rescan prompt that punishes the user for not rescanning is
how a safety app gets deleted. Null last_scanned (hand-built home, never scanned) is not stale —
it is a different state, and it gets a different, gentler prompt.

WHAT HAPPENS TO SAVED HOMES
The saved-homes list Home currently owns must stay reachable — multi-home is a real use case
(a second home, a relative's house). Put it behind a home-switcher in the header rather than
deleting it, and make the currently-active home unmistakable.

EMPTY / LOADING / FAILURE
- First run, post-interview, pre-scan: the list already has real items ("Map your house" first).
  This screen is never truly empty; make that first state feel like a plan, not a void.
- Backend unreachable: use the existing BackendFailure classifier and BackendFailureBanner. Do not
  invent a second failure notice. 502 = "AI unavailable", no retry; 503 = busy, with retry.
- Checklist generation requires the backend; cache the last generated checklist locally so the Home
  tab still renders something useful offline, clearly marked as last-known rather than live.

UI QUALITY BAR
Theme.swift's semantic scale only. NO new colours. Route orange stays reserved for lit routes and
exits — hazard chips must NOT use it for the fire chip in chrome; use the dark-amber advisory
treatment. Dynamic Type, VoiceOver on every row (announce title, hazard, done-state), both
orientations. Use the ui-ux-pro-max skill for the visual pass.

ACCEPTANCE
- Fresh install → interview → Home tab shows a populated, sectioned, hazard-tagged checklist with
  "Map your house" first.
- Placing a gas shutoff in the editor flips the shutoffs item to done with no manual tick.
- A no_viable_safe_room finding appears pinned at the top, visually distinct.
- Every row either deep-links somewhere real or explains a physical-world action. Zero dead taps —
  verify by tapping every single row on a device, not by reading the code.
- Airplane mode renders the cached checklist with an honest last-known marker.
- xcodebuild test green (re-run before believing a red).
- swift-scenekit-reviewer agent run and addressed.

CLOSE OUT
Update docs/tracker/TODO.md, write the session note, log decisions (especially the derive-vs-store
rule and the non-punitive rescan ruling), and file every rough edge you noticed but did not fix as
a TODO line naming its next action.
```
