S7.6 — The hazard hunt: tagging what no scan can see · ~8h · Prereqs: S7.1 (blocks S7.7, S7.9)

Context: the scan finds wardrobes and stoves; it will never find the space heater, the water
heater in the garage closet, the mirror over the headboard, or whether anything is strapped to
a stud. Those facts come from the user, and today the editor cannot even record them — the
schema has carried `secured` UI-less since 2.0, and 2.1's elevation/mounted fields (S7.1) need
controls too. This session gives the editor the missing object controls and a guided,
room-by-room "hazard hunt" that asks the user a handful of concrete, skippable questions per
room. Zero network calls — the AI account may be dry, and the front door of a safety feature
cannot depend on billing. The design bar: this is data entry that must not feel like a form.

MISSION
Two deliverables: (1) complete the object inspector — secured toggle, elevation/mounted
controls, size/height steppers, the four new categories; (2) the hazard hunt — a guided
per-room pass that captures scan-invisible hazards as ordinary FloorObjects and secured flags.
Everything flows through HomeModelStore; nothing mutates the model from a view.

WHAT TO BUILD
1. Reducer actions: setObjectSecured(objectId:secured:), setObjectMounted(objectId:mounted:),
   setObjectElevation(objectId:elevation_m:) — validated (elevation >= 0), undoable, and
   round-tripping like every existing action. Extend resizeObject only if it does not
   already carry what the inspector needs.
2. Inspector: the category picker already exists; add the secured toggle (with a one-line
   plain-language caption — "strapped to the wall?"), size/height steppers, and
   elevation/mounted controls that appear only when relevant (elevation for mounted
   things; do not make a floor wardrobe ask about mounting height). While in this file:
   the tracker's long-standing `setOpeningWidth has no UI entry point` item is the same
   inspector pattern — close it here if it is still open on the tree, and check it off in
   TODO.md as part of this session.
3. FurnitureFixture: real geometry for bookcase (shelf lines), tv (thin slab — honor
   elevation_m in placement), water_heater (cylinder), heat_source (low box; the White
   Model rule holds — no colour, form only). Objects with elevation_m > 0 render at their
   base height in DollhouseScene's makeObject path; keep the one-node object:<id> naming,
   selection and dragging depend on it.
4. The hazard hunt: an entry point on the House tab (not a modal ambush), iterating rooms
   with 3-5 concrete questions keyed to room type — bedroom: "anything tall and heavy near
   the bed? anything mounted above it?"; any room: "portable heater here?"; garage/utility:
   "water heater — strapped?". Each yes drops a correctly categorized object into the room
   (user positions it with the existing drag tools) or sets secured on an existing one.
   Every question skippable, progress resumable, redoable later per room. Scan-derived
   low-confidence objects surface for confirm/fix through the existing flagged-items
   review pattern rather than a parallel one.
5. Copy discipline: the hunt's questions are questions, not safety claims. Any sentence
   that asserts risk belongs to the engine/checklist (cited); the hunt only collects
   facts. This keeps grounding law intact without needing citations in UI copy.
