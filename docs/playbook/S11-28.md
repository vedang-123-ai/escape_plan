# S11.28: Sign-in routes stop blocking the server and stop allowing unlimited guesses · ~3h · Lane E (backend) · Prereqs: S11.27 (client-key helper) (blocks S11.43)

Context: `/auth/register` and `/auth/login` are `async def` and call the synchronous Argon2 hasher directly (64 MiB,
t=3, p=4), so each hash blocks the single asyncio event loop. The audit measured 36.5 ms per verify on an M-series Mac;
the free Render instance is much slower. While a hash runs, no other request is accepted or dispatched, `/health`
included. Neither route has a rate limit or lockout, and registration needs no verification, so credential stuffing is
unlimited and a modest login flood stalls the whole demo backend. `needs_rehash` exists but is never called (AUD-011),
so any change to Argon2 parameters would never reach existing hashes.
