S7.3 — Scan objects: stop throwing them away · ~7h · Prereqs: S7.1 (blocks S7.8)

Context: RoomPlan already detects beds, sofas, storage, stoves and televisions with full 3D
oriented bounding boxes, and the app already writes them to `apple-raw.json` on device — then
drops them from its own wire format, and `/convert` ignores them. This session closes that gap
end to end: capture → export → parse → HomeModel objects with real categories, confidence, and
(for mounted things) real elevation. It is the single highest-leverage session in the arc: the
demo line "the scan found your furniture and measured the hazard" is built here. The scan
converter is also the repo's most assumption-laden module — its README documents which format
guesses are unverified against real hardware — so every mapping you add must be triaged, not
trusted.

MISSION
Carry RoomPlan's detected objects through the whole pipeline: CapturedRoom.objects → the raw

THE TWO HALVES
1. iOS export. RawScanExport formatVersion 2 → 3: RawScanRoom gains an objects array
   (RoomPlan category string, confidence, dimensions, full 4x4 transform — hand-rolled like
   the existing surfaces, for the same reason: Apple's synthesized encoding is undocumented).
   Extend the ScanRoomConvertible bridge to expose CapturedRoom.objects. apple-raw.json
   keeps being written unchanged — it remains the calibration diff.
2. Backend parse + convert. RPObject model in roomplan.py (extra="ignore", like RPRoom);
   category map EXACTLY per docs/object-hazard-spec.md §7 — bed/sofa/table/storage pass
