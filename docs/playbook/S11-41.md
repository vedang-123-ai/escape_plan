# S11.41: Home ids are validated on every write, and the library never lists a home it cannot open · ~2h · Lane D (iOS) · Prereqs: S11.21, S11.40

Context: `HomeDocumentStore.url(for:)` appends the `home_id` to the Homes directory unsanitised. Ids arrive from the
server (sync pull) and, until S11.40, from hand-edited files; `../` segments would escape the directory. Separately,
`list()` reports the id embedded in each document while `load()` looks up by filename, so a file whose name and embedded
id differ is listed but cannot be opened. It is exploitable only by someone who controls the user's own account or
files (hence P3), but the mismatch case was reachable through the Files app.
