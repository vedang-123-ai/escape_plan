# S11.37: Failure messages tell the truth: cancelled, slow server, app and server disagree · ~2h · Lane D (iOS) · Prereqs: S11.23, S11.29 (server chat deadline)

Context: `BackendFailure` is the app's one error classifier (good), but it files three different things under the
wrong message. (1) A cancelled URLSession request is `URLError(.cancelled)`, not `CancellationError`, so it falls
through to "Couldn't reach the server. Check your connection, or the server address in Settings" (AUD-014, AUD-046).
(2) `.timedOut` sits in the "offline" set. The audit measured a 51 s cold start on the free Render instance, and chat's
60 s timeout cannot absorb that plus model time. So the first Assistant message after ~15 idle minutes fails with
"You're offline" on a phone that is online (AUD-032). (3) A `DecodingError`, meaning the app and server disagree after
a deploy, also shows "Couldn't reach the server" and sends the user to Settings (AUD-046).
