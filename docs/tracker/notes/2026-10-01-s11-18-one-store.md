## What happened

Re-confirmed AUD-019 on `origin/main` 7b22cb6: `grep -rn "HomeDocumentStore()" escape_plan` found seven screen-level
call sites (SettingsScreen:243, BuildFromPlanView:212, HouseScreen:207 and :213, ProfilesScreen:33,
OnboardingState:155, DrillScreen:755). Each now uses the library's store, injected the way the screen's caller
already reaches the library:

| Screen | How it gets the store |
| --- | --- |
| `HouseScreen` | `library?.store` from the `library:` it was already given by both callers (HouseTab, HomeScreen). Nil only in the preview, which never saves. |
| `HouseScreen.init()` (the second one) | **Deleted, not injected.** It had no call sites at all. |
| `ProfilesScreen` | New required `store:` init parameter. It has no live caller (AUD-020; S11.20 makes it reachable), only its preview, so S11.20 inherits an injected store. Not made reachable here. |
| `SettingsScreen` | `@EnvironmentObject library`. Store swap ONLY: it still shares the most recently modified home, not the active one (AUD-027), and can still share an unreviewed draft (S11.17 line). Both are S11.38's. |
| `BuildFromPlanView` | `@EnvironmentObject library` (see "sheet" below). |
| `DrillScreen` | `@EnvironmentObject library`, one line in `load()`. No draft guard added (S11.36's). |
| `OnboardingState` | `documentStore` is now required and non-optional; the `try HomeDocumentStore()` fallback in `store()` is gone. |
| `OnboardingFlowView` | Gained `init(documentStore:onFinished:)`; ContentView passes `library.store`. **Owned-files exception**, logged in `docs/decisions.md`. |

**Environment reach, checked rather than assumed** (a missing `@EnvironmentObject` crashes at access, not at
type-check). ContentView applies `.environmentObject(library)` to its TabView. Every presenter of Settings, BuildFromPlan
and Drill sits inside that subtree: Settings is a tab and the `BackendFailureBanner` sheet (hosted only by screens
inside the tabs); BuildFromPlan is a `.sheet` attached inside HomeScreen, which itself reads the same
`@EnvironmentObject library`, and a sheet inherits the environment of the view it is attached to; Drill is a
`navigationDestination` from HomeScreen and TasksScreen. The onboarding cover is the exception: ContentView attaches
`.fullScreenCover` OUTSIDE the `.environmentObject` modifier, so the cover would not get the library. That is why
onboarding gets the store passed explicitly instead.

Tests: three new cases in `escape_planTests/HomeLibraryEditorSeamTests.swift` put the library on a temp-directory store
and prove a save made through the screen's store lands in that directory and shows in the library:
`testHouseScreenSavesThroughTheLibrarysStore`, `testProfilesScreenSavesThroughTheStoreItIsGiven`,
`testOnboardingSeedsIntoTheLibrarysStore`. (By construction the House case cannot pass against the old code, whose
store pointed at `Documents/Homes`; not mutation-run.) Settings, BuildFromPlan and Drill read an environment object, which a unit test cannot host
without SwiftUI; the acceptance grep and the reviewer's presenter audit cover them.
