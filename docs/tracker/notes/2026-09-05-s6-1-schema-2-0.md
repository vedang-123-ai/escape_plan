## What happened

The five additions went in as specified and nothing was added beyond them. What took the time
was everything the prompt did not know about.

**The additions.** `profile.tags` += `hearing_impaired`/`vision_impaired` (routing-neutral);
optional top-level `household` (tenure, existing_equipment); per-floor `safety_points[]`;
`object.secured`; `meta.last_scanned`. Deliberately absent: no `safe_room` (S6.3 computes it),
no checklist state, no peril enum.

**Backward compatibility is option (a), and it is a verified property rather than a judgement
call.** Every 2.0 addition is optional, so `bungalow.json` with only its version string changed
validates against the new schema with **zero** errors and gains no keys. pydantic accepts
`{1.1, 2.0}` and normalizes to 2.0 in memory; `SchemaMigrator` gained the 1.1 → 2.0 re-stamp.
Nothing is rewritten on disk without an explicit save.

**Gate — all four green.** Backend **339** passed / 13 live-deselected (was 310).

## Decisions / surprises

Five things the session prompt does not mention, each of which would have cost a later session
real time. The first three came from running the schema-contract-guardian *before* touching
anything, which is worth doing again.

1. **`escape_plan/Fixtures/*.json` are byte-identical copies of `schema/fixtures/`**, bundled
   into the app because it cannot read outside its bundle — and **nothing tested that they stay
   in sync.** They went stale the instant the contract moved, and the app would have shipped
   v1.1 homes against a v2.0 build with nothing failing. Re-copied, and there is now a test
   (`test_the_apps_bundled_fixtures_match_the_contracts`). The copies are fine; the absence of
   a guard was not.

2. **`PersistenceTests` used `"2.0"` as its "document is too new" sentinel.** The moment 2.0
   became current, that test asserted the opposite of its intent. Moved to `"3.0"`, and every
   version assert in the Swift tests now references `SchemaMigrator.currentVersion` /
   `HomeModel.currentSchemaVersion` rather than a literal, so the next bump cannot invert them
   the same way.

3. **`profile.tags` was `required` in the schema but optional in BOTH mirrors** — a three-way
   disagreement predating this work. Fixed here because the version was open; leaving it means
   the next `tags` mismatch gets misattributed to the 2.0 bump.

4. **Adding two `ProfileTag` cases broke three exhaustive switches** (`RouteNarration.tagName`,
   `ProfileEditorView.displayName` and `.routingHint`). This is the strict-enum design in
   `Enums.swift` working exactly as documented — it fails loudly rather than silently
   mislabelling someone's home. **EditorCore did not catch it**, because `Export/` and
   `Screens/` are not in the symlinked subset; only the full `xcodebuild` run did. Worth
   knowing: a green `swift test --package-path tools/editorcore` does NOT mean the app compiles.
   `routingHint` mattered most — it is the VoiceOver hint explaining what a tag does to routing,
   so for these two it has to say plainly that it changes nothing.

5. **`HomeModel.decoder` used `.iso8601`, which cannot parse fractional seconds**, while
   pydantic round-trips microseconds happily. Latent and invisible because no fixture carries
   them — but `meta.last_scanned` is a new backend-writable datetime, so the trap became
   reachable and would have surfaced only on device. Fixed at the point the change created the
   exposure.

**Process gap worth fixing.** The schema-guard hook matches `Edit|Write` only, so editing
`schema/homemodel.schema.json` through a Bash heredoc — which is what happened here — produces
no confirmation prompt at all. `CLAUDE.md` advertises that guard unconditionally. Nothing was
bypassed in substance (S6.1 is the one session permitted to change the schema), but it should
not be relied on. Filed in TODO with a next action.

**Tracker correction.** TODO said system `python3` runs everything and `backend/.venv` does not
exist. On this machine the reverse is true: system `python3` cannot import pydantic, and
`backend/.venv/bin/python` (3.13.9, pydantic 2.13.4) is the only interpreter that runs the
suite. Both directions have now been seen; the note now says to check.
