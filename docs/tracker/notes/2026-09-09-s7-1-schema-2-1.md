## Decisions / surprises

- **The guardian caught a defect I created.** Widening the `schema_version` enum made
  `testCurrentVersionMatchesTheSchemaContract` vacuous — it asserted *membership*, so it would
  have passed with `currentVersion` reverted to any of the four values. The one test named for
  catching version drift had quietly stopped being able to. Generalisable: **a guard that checks
  membership in a set gets weaker every time the set grows,** and the growth lands in a different
  commit than the guard.
- **A test's premise had to change, not just its expectations.** `test_obstacles.py`'s
  no-golden-churn guard asserted straight legs for `bungalow` and `twostory` *because they have
  no objects*. Seeding `twostory` is a hard S7.1 requirement, so the premise became false. The
  fixture list is now derived with a non-empty assert instead of hardcoded. **Real cost, recorded:**
  the derived set is now only `bungalow.json`, so the property is no longer checked on a
  multi-floor home.
- **`bookcase` and `water_heater` currently produce no mitigation item at all**
  (`checklist.py:504` filters on `{wardrobe, storage, appliance}`). So a user who picks the newer,
  *more accurate* category loses a recommendation they would have gotten yesterday. Leaving it is
  still right — fixing it here would collide with S7.4's `hazard.topple.<id>` items and produce
  the duplicate strap-it item ruled out at scoping — but it is an S7.4 obligation now, not a
  vague intention.
- **Routing is elevation-blind and the fixture hides it.** A mounted TV still erodes walkable
  floor. It does not bite today only because the seeded TV overlaps the bed, which already blocks.
- Surprise worth knowing: `backend/app/convert/converter.py:289` stamps `"1.1"` and relies on
  HomeModel's before-validator to migrate it forward. Safe **only** while every migration is a
  stamp rewrite. Left alone (S7.3 owns the converter), condition written at the call site.
