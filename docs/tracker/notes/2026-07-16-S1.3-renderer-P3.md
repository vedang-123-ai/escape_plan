## What happened

Built the renderer as two layers, deliberately split:

- `escape_plan/Renderer/DollhouseGeometry.swift` — pure geometry, no SceneKit nodes, no I/O. Coordinate mapping, polygon centroid, wall dedup, and the parametric opening placement all live here, so they're unit-testable without a device or a renderer.
- `escape_plan/Renderer/DollhouseScene.swift` — `DollhouseSceneBuilder.build(HomeModel) -> (scene, issues)` plus a `DollhouseScene` handle exposing `setExplode(_:)` / `setFloor(_:visible:)`.
- `DollhouseSceneView.swift` (UIViewRepresentable, `allowsCameraControl` = orbit/pan/zoom), `DollhousePalette.swift`, `FixtureLibrary.swift`, `DollhouseDemoView.swift` (demo shell only).
- `escape_plan/Models/Generated/HomeModel.swift` — throwaway Codable mirror, see Integration points.

What's rendered: room polygons extruded per floor (floor slab via `SCNShape` + room-type accent), semi-transparent walls, opening markers placed parametrically from `edge_index` + `t0`/`t1` (never absolute coords), straight-flight stair proxies, floors stacked by `level`, billboarded room labels, exploded-view slider + per-floor visibility toggles.

18 XCTest cases in `escape_planTests/DollhouseRendererTests.swift` cover what a screenshot can't: every fixture decodes; every opening in every fixture resolves parametrically; shared walls dedup to the expected count; explode clamps and returns to rest; floor toggles work; dangling `wall_segment` refs return nil rather than silently placing at the origin. **These have compiled but never executed** — no runtime.

Two bugs I caught reviewing my own code before any of it ran, both worth knowing about:
- `DollhouseDemoView` originally rebuilt the entire `SCNScene` on every `body` evaluation — i.e. on every slider tick. Now built once per fixture via `.task(id:)`. This would have shown up as exactly the kind of stutter the 60fps criterion is about.
- `renderingOrder` is **per-node and does not inherit**. I'd set it on the billboard holder instead of the node carrying the text geometry, so the "labels stay legible through walls" behavior wasn't actually on.

## Decisions / surprises

All seven S1.3 rows promoted to `docs/decisions.md`. The ones that will bite someone else:

- **Opening size vs. placement.** The marker is centered on the *midpoint of [t0, t1]* and sized by *`width_m`* — per the schema, the t-range is placement, not size. If you expected the marker to span t0→t1, it doesn't, and that's on purpose.
- **Shared walls are deduplicated.** Adjacent rooms each own the shared wall in their own polygon. Rendering both puts two coplanar transparent boxes in the same place and they z-fight. Keyed on the unordered, 1mm-rounded endpoint pair.
- **Transparent walls set `writesToDepthBuffer = false`.** A transparent surface that writes depth hides what's behind it — which for a see-through dollhouse is the entire point of the screen. If someone "fixes" this back to the default, the dollhouse goes opaque-ish and nobody will understand why.
- **Surprise: this Mac had no iOS platform installed at all** (Xcode 26.6, zero simulator runtimes, `simctl list devices` empty). The Simulator *SDK* is present, so compiling works; only booting doesn't. The incantation that compiles without a runtime is `xcodebuild build -project escape_plan.xcodeproj -alltargets -configuration Debug -sdk iphonesimulator -arch arm64 CODE_SIGNING_ALLOWED=NO`. Note **`-configuration Debug` is required** — the `-target`/`-alltargets` default is Release, which has `ENABLE_TESTABILITY=NO`, and `@testable import escape_plan` then fails with a confusing "unable to resolve Swift module dependency to a compatible module" error. Scheme-based builds (`-scheme`) can't resolve a destination at all with no runtimes installed.
- Stair `kind` L and U render as a **straight-flight proxy**. The schema stores a footprint + kind for proxy geometry only; an L-shaped proxy would be inventing geometry the model doesn't carry.
- In exploded view the stair proxy **stays with its lower floor** (it's a child of the `from` floor node), so it visibly detaches from the upper floor as you explode. Correct-ish and honest, but it will look odd in a demo — worth revisiting if the exploded view gets screen time.
