# S11.33 — Photo import sends a real JPEG the AI can read

- **Who:** Claude (for Anish)
- **Date(s):** 2026-10-03
- **Status when I stopped:** done and merged. AUD-024 client half fixed; the live check (funded `/build`) is S11.49's.

## What happened
- New `escape_plan/Networking/ImagePreparation.swift` (ImageIO + CoreGraphics, `nonisolated`, no UIKit/SwiftUI):
  - `photo(Data)`: decodes HEIC/JPEG/PNG/Live Photo still with a CGImageSource thumbnail (primary image index,
    `WithTransform` for EXIF orientation, never upscales), caps the long edge at 1568 px, draws onto white sRGB, and
    encodes JPEG at 0.8 → 0.6 → 0.4 until base64 fits 10,000,000 chars. No metadata is copied.
  - `pdfFirstPage(Data)`: CGPDFDocument, crop box, `/Rotate` honoured, rendered to a 1568 px PNG.
- `APIClient.build(description:image: PreparedImage?)`: no raw bytes and no media-type default anywhere.
  `BuildRequest.image_media_type` is optional and omitted with no image.
- `BuildFromPlanView`: the image is prepared at pick time, off the main actor. A "Preparing your floor plan…" row
  shows and Build stays disabled until it's ready. A failure keeps any previous attachment, shows a message in the
  attach section and announces it to VoiceOver. PDFKit/UIKit rendering is removed.
- Privacy copy (`AccountPrivacy`) corrected: photos now leave without location/date (owned-files exception, logged).

## Decisions / surprises
- The 1568 px cap now applies to PDFs too (they used to render at up to 3000 px). See decisions.md.
- `swift-scenekit-reviewer` found no must-fix. Acted on everything it raised: `nonisolated` (the app target defaults
  to MainActor, and `typecheck-ios.sh` doesn't pass that flag, so it can't see the warning; BLOCKERS line), the
  build-without-photo race, PDF off the main actor, crop box, primary image index, an attachment-specific announced
  message, rotation/crop/GPS tests, deterministic fixtures (reused `SeededGenerator` from StoreInvariantTests), and
  renaming an overclaiming test.
- "Undecodable sends nothing" is enforced structurally: `build` accepts only `PreparedImage`, which garbage cannot
  become. The view half (message shown, nothing attached) is not unit-tested.
- The Anthropic account's credit state was not touched; no test uses the network.
