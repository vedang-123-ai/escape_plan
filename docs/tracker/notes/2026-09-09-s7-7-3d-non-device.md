## What happened
- Built the pathway from a checklist tap to a camera focus in the 3D view:
  - `HomeScreen` now hands `HouseScreen` the tapped checklist item's **id** (`focusItemID`), not a
    pre-parsed `Selection`. Resolution against actual object ids happens in `HouseScreen`, once the
    real `HomeModel` is loaded — the id grammar in `backend/app/scoring/checklist.py` is not safe
    to parse without the model (see next point).
  - New `escape_plan/Models/ChecklistItem+Objects.swift` / `ChecklistObjectIDs.resolve` maps
    `hazard.<rule>.<obj>`, `mitigation.secure.<obj>[.renter]`, and
    `routes.{blocked_opening,narrows_route}.<room>.<obj>[-<obj>…]` to real object ids, matched
    against the ones the home actually has (not split on `-`, since object ids themselves contain
    `-`: `obj-1a2b3c4d` from the converter, a raw UUID from the Hazard Hunt). A row pointing at a
    deleted object resolves to nothing, never to a wrong neighbor.
  - `OrbitCameraRig.focus(on:)` and `UnifiedSceneController.focusCamera(on:)` (added earlier in
    this session) reuse the existing `highlightPlacement` pattern — no second camera behavior.
- Advisory emphasis: a hazard-flagged object gets an `advisory_ring` (`SCNTorus`, same shape as the
  selection ring) at its own floor plane. Colour now reads from `Theme.cautionComponents.dark` at
  runtime instead of a re-typed hex literal, so the 3D advisory and the UI chrome cannot drift
  apart. One treatment for every rule; severity differentiates via the checklist text, not colour.
- **Found and fixed a real renderer bug while writing the emphasis test, not going looking for
  one:** `DollhouseScene.GhostEntry` never recorded a node's as-built `renderingOrder`, so
  un-ghosting a `.structure` node (walls, fixtures, and — since S7.6 — furniture objects) was a
  silent no-op (`node.renderingOrder = node.renderingOrder`). Because the builder opens on the
  top floor, every object on every other floor got stuck at `RenderOrder.ghostWall` (90) instead
  of `RenderOrder.objects` (2) the first time that floor was ghosted, and never recovered when the
  floor became active again. Fixed by capturing `solidRenderingOrder` once at classification time
  (before any ghosting) and restoring that instead of self-assigning. Caught by
  `testAdvisoryRingLandsOnTheNamedObjectsOnly` failing `90 != 2` on its first honest run against the
  two-floor `twostory` fixture — exactly the "ghost-floor stacking with mounted objects" case
  S7-7.md names.
- Cleaned up two mechanical defects left by the interrupted Antigravity/Gemini session: a
  duplicate `import SwiftUI` in `UnifiedSceneController.swift`, and the initial cited-color literal
  noted above.
