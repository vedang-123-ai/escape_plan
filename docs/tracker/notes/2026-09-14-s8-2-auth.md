## The dependency research was the most valuable part

The playbook and most tutorials assume `passlib`. **passlib has had no release
since 2020 and now hard-fails against bcrypt 5.0.0** — its own backend probe
feeds a >72-byte secret to `hashpw`, which changed from truncating to raising.
It declares no bcrypt upper bound, so a clean install today picks bcrypt 5 and
breaks on first use. Verified empirically, not inferred from bug reports.

**PyJWT below 2.13.0 carries five CVEs** from 2026-06-15, including an algorithm
allow-list bypass and a public JWK being accepted as an HMAC secret (forged
HS256 tokens). That is a floor, not a preference.

Both would have been invisible had the libraries been pinned from memory.

## Four judgement calls (all in `docs/decisions.md`)

1. **Argon2id via argon2-cffi**, not passlib, not bcrypt, and not `pwdlib` —
   which is what FastAPI's current tutorial recommends, but is 0.3.1 Beta with
   one maintainer and is a thin wrapper over argon2-cffi anyway. Six weeks from
   submission, the wrapper did not justify a 0.x dependency.
2. **PyJWT `>=2.13.0`**, with two dangerous defaults overridden: `algorithms` is
   always passed explicitly, and `require: [exp, iat, sub]` is set because
   **PyJWT only validates `exp` if the claim is present** — a token omitting it
   never expires.
3. **A JWT secret under 32 bytes is refused**, not warned about.
4. **Three anti-enumeration choices**: login always runs a verification (against
   a dummy hash for unknown emails, so timing does not reveal who has
   registered); the user is re-read per request, so deleting an account revokes
   access immediately; another user's home id is 404, not 403.

## Two real bugs found by tests

- **Cross-owner writes.** `replace_one` with an owner-scoped filter does not
  quietly no-op when the id belongs to someone else: the filter misses, Mongo
  attempts an insert, and it collides on `_id`. Data was never at risk, but it
  surfaced as an unhandled driver error. Now `HomeNotOwned` → 404. This was only
  visible after the fake was fixed to model `_id` uniqueness — the fake had been
  hiding it.
- **Invalid email → 500.** The address reached `User()` inside the handler, where
  the `ValidationError` was unhandled. Now validated at the request boundary,
  sharing one `normalise_email` rule with the storage model.

## NOT verified

No MongoDB was ever contacted. The unique email index — the account-takeover fix
— is written and called on connect, and the duplicate race is tested against a
fake that enforces it, but **no real server has ever created it**. `cloud_repo`
identifies `DuplicateKeyError` **by class name** to keep pymongo out of the
import path; a driver rename would silently break the 409 path. Both in
`BLOCKERS.md`.

`JWT_SECRET_KEY` is set nowhere. Until it is, `/auth/*` and `/homes` return 503
by design. Owner action; the iOS work in S8.3/S8.4 will need it.
