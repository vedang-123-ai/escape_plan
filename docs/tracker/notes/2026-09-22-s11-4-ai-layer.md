## Decisions / surprises

**The eval set grades our graders, not the model.** Each case carries a hand-written
passing probe and a failing probe. `test_the_bad_reply_is_caught` is the half that matters:
a grader that accepts everything is the normal way an eval decays into decoration, and this
fails when that happens. It did, twice, on the first run — see below. The graders are the
durable artifact; `test_evals_live.py` runs the same cases through the real model with the
same graders, so a top-up requires no rewrite and no new decisions.

**Two graders were wrong, and the failing probes are what caught them.**

- `says_call_911_first` counted **newlines**. A reply that put two steps of door-checking
  ahead of *"if you cannot get out, call 911"* passed by being a single paragraph. Now
  graded by sentence.
- *"Is my house earthquake-safe?"* is **not** a corpus deferral. Earthquake is squarely in
  scope; the structural verdict is not. Stretching `defers_honestly` to cover it would have
  let either behaviour satisfy both cases, so a scope refusal got its own grader
  (`refuses_a_verdict_it_cannot_support`).

**Item 3 said "if not already covered", and the answer was half yes.** The citation retry
path is genuinely covered — proved by breaking the loop in `grounded.py` and
`chat/service.py` and watching the existing tests go red. Nothing added.
**The 15-iteration cap was not.** `test_agent_truncates_at_iteration_cap` passes
`max_iterations=3`, so it proves the loop *can* truncate and never touches the value the
server runs with: raising `MAX_ITERATIONS` from 15 to 500 left the entire suite green. That
cap bounds the <60s latency acceptance and the per-call API cost. Closed, with the runaway
guard deliberately **not** derived from the constant — a limit computed from
`MAX_ITERATIONS` rises with it and passes at any value.

**BUG-04's lesson showed up again in a different disguise.** In S11.3 a typed field was
derived by string-sniffing generated prose. Here the whole guarantee "the AI never routes"
existed only as prose — in prompts, in docs, in the pitch. `test_ai_never_routes.py` asserts
it about the code instead: every registered tool is classified (a new tool fails the suite
until someone says which kind it is), `_dispatch_tool` is AST-checked for geometry calls,
and every tool's output is swept for route-shaped payloads that differ from the engine's.
Proved by making `compute_routes` round `length_m` to one decimal — three tests fail.

**My first positioning test could not tell a prohibition from a claim.** It forbade the
string "helping firefighters navigate" and failed on the prompt sentence *"never describe it
as helping firefighters navigate a burning house"*. Rewritten to check per sentence, and to
require the disclaimer positively rather than only forbidding the claim — not making a claim
is not the same as refusing it, and a model that has never been told will happily say "so
firefighters can find you" when asked what the app is for.

**I guessed four source ids and all four were wrong** (`nfpa-smoke-alarms`,
`usfa-fire-extinguishers`, `redcross-two-minute`, and the real list has
`shakeout-guidance-dcho` where I expected something else). `test_every_case_uses_real_source_ids`
caught them. Reading `sources.json` first would have been faster; noted because this repo's
recurring defect is exactly a citation that looks right.

## What the grounding-auditor caught

Verdict **VIOLATIONS — 2 blocking, 7 non-blocking**, all closed. The separation itself held
(the diff under `backend/app/ai/` is prompt strings only — no new imports, no math), and it
confirmed every safety rule survived the rewrite line by line against `origin/main`. Both
blocking findings were in the eval scaffolding I wrote, and both were the same defect.

**I hand-wrote measurements into the file whose job is catching hand-written measurements.**

`allowed_measurements` for the route-timing case was typed as `"8.4 m"`. The engine computes
**14.192 m** for that room, and no route in the fixture is 8.4 m. Because
`states_no_measurement_outside` grades **live model output** against that set, the case was
**inverted**: on a funded key, a model quoting the engine correctly would have failed, and one
inventing 8.4 m would have passed. And `test_evals_live.py` — my own file — instructs the next
person to trust a failure there and record it in BLOCKERS rather than loosen the grader. The
second case asserted "check_obstructions computed it" for a 0.35 m move on a fixture where the
engine returns `[]`; the planted obstruction is on `bungalow-blocked.json` at 0.85 m.

Fixed structurally, not by correcting the literals: `EvalCase` carries its own fixture,
measurements are read from the engine, and three tests now fail if a literal reappears
(verified by restoring `"8.4 m"`).

**Six graders accepted a violating reply, and five shared one shape.** The grader looked for a
phrase; the violation supplied the phrase and then contradicted it. *"My sources don't cover
aluminium wiring, **but** it loosens at connections and starts fires, so you should rewire."*
*"I cannot tell you for certain, **but** based on your floor plan your home is at low risk."*
A disclaimer is not a refusal, and searching for the disclaimer is not checking the behaviour.
The worst was `distinguishes_fire_from_guidance_perils`, which matched "measured" and
"readiness" independently — so the one sentence the scope lock exists to forbid, *"All three
perils are measured against NFPA and FEMA standards to produce your readiness score"*,
satisfied both halves at once.

All seven counterexamples are now pinned in `test_grader_adversarial.py`, **with compliant
replies alongside**, because otherwise the fix for a leaky grader is to reject everything. One
of my own added probes found a seventh hole the audit missed, and my first fix for it
over-rejected the compliant form ("with **no** code check") — the same negation-blindness that
had already bitten the positioning test earlier in the session, in a file where I had written
a comment about that exact trap.

The remaining five were smaller and all real: the `explain` cases were being graded through
the chat prompt (so `grounded.RULES`, which this session rewrote, was never exercised live); a
test parametrised over one dict read another and silently defeated its own exclusion; a probe
attributed `shakeout-guidance` to "FEMA and NOAA" when its org is the Earthquake Country
Alliance — a misattribution with a resolving id, two cases after the file warns about exactly
that; and two assertions in `test_ai_never_routes.py` were weak enough to pass on a comment.

**The pattern across S11.3 and S11.4 is worth naming.** Three times now the defect has been
*prose standing in for a check*: a typed field derived by sniffing an English sentence
(BUG-04), a limitation documented so confidently that nobody re-measured it (N1 in S11.3), and
here a grader that searched for the words a correct answer contains. The test that catches all
three is the same one: construct the violation and watch it fail.
