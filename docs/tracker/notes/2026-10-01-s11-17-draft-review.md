## What happened

Re-confirmed AUD-023 on `origin/main` `3c32ab4` before changing anything: `HomeScreen`'s `BuildFromPlanView` completion
only called `switchHome(to:)`, `ReadinessStore.load` → `fetchScore` POSTed `/score` for whatever home was active, and
nothing in ReadinessStore looked at `hasAIDraftContent`. House alone refused (`needsDraftReview` gates `/routes`).

Changes (all inside OWNED FILES):

- **`ReadinessStore`**: `needsDraftReview` = `activeHome?.hasAIDraftContent` (House's predicate, not a copy). `load()`
  now reads the home first and, for a draft, clears breakdown + failure and returns before both the `ScoreCache` and
  `/score`. `fetchScore` re-checks, so every path (load, `rescore`, `toggleDone`, `replaceActiveHome`) is covered.
- **`HomeScreen`**: Import Plan completion → `openDraftForReview`: select the draft, then `router.openHouse` (the
  pre-revamp BetaScreen behaviour). For a draft, Home shows the review card instead of score / Up next / quick actions
  (so no drill entry), and the subtitle says "AI draft, not reviewed yet" instead of "Built by hand — not yet scanned".
- **`TasksScreen`**: shared `DraftReviewNotice` (card, "Review in House" → router). Shown instead of the checklist; the
  Family plan block (meeting point → PDF export, practice reminder, Share with fire department) is hidden for a draft.
- **`ScoreScreen`**: shows the notice for a draft.
- **`escape_planTests/ReadinessStoreTests.swift`** (new, app runner): spy `URLProtocol` on an ephemeral session handed
  to `APIClient(session:)`. The only seam: `rescore` now returns its `Task` (`@discardableResult`) so a test awaits
  it instead of sleeping. Five tests: no `/score` for a draft through load, rescore and replaceActiveHome (and
  `items` empty); switching from a scored home with a failure showing to a draft clears breakdown, failure and items;
  a score cached before the fix is not shown; after confirm, a draft-era cache is not shown while `/score` fails; the
  control — confirm through House's own `.confirmAIDraft` EditAction, save, reload → exactly one `/score`.
  Mutation-checked: deleting the `fetchScore` guard fails `testUnreviewedDraftIsNeverSentToScore`.
  `AIDraftReviewTests` unchanged (predicate unchanged).
- After review: a response for a request started before the draft became active is dropped (`!needsDraftReview`
  after the await, success and failure), `items` is empty for a draft (tab badge, Up next, Tasks header), and a home
  seen as a draft this launch skips its cache after confirm.

**How Home comes back to a real score after confirm (nuance 2):** no new work needed. `confirmAIDraft` commits →
HouseScreen `onCommit` → `autosave` writes the file → `onModelChanged` → `HouseTab` calls `library.refresh()` and
`readiness.load(api:)`, which re-reads the file from disk, finds no `ai_plan`, and scores. Observed in the simulator
(below). S11.18/S11.19 not needed for this.
