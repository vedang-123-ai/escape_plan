- **Who:** P3

- **Status when I stopped:** score screen built, building clean, math cross-checked against

## What happened

- New `ScoreScreen` (pushed per-home from HomeScreen via leading swipe "Score" / context
  menu — not a sixth tab, see decisions.md): big animated score number with color tint,
  "How it's scored" section rendering the backend's five components as `DisclosureGroup`
  rows (progress bar + earned/max collapsed; backend `detail` + `rationale` expanded),
  then checklist sections by category. Scoring items get toggles; routes/findings/
  recommendation items render as advisory (info icon, "These don't change the score.").
- New files: `Models/ScoreModels.swift` (Codable mirror of the /score contract,
  snake_case), `Persistence/ChecklistStateStore.swift` (UserDefaults,
  `checklistState.<home_id>`), `Networking/APIClient+Score.swift` (POST /score;
  APIClient.swift untouched), `Screens/ScoreScreen.swift`. Only existing file edited:
  `HomeScreen.swift`.
- Live update flow: toggle → persist state → cancel in-flight request → re-POST /score →
  `withAnimation(.snappy)` swap of breakdown (numericText makes the score count up/down).
  Stale breakdown stays visible while updating; refresh failure shows an inline error row
  with Retry and toggles keep their state; first-load failure is a `ContentUnavailableView`.
- Verified: `xcodebuild` clean (only a pre-existing Capture/ actor-isolation warning), and
  live `/score` cross-check — bungalow 75 → 80 (`practice.meeting_point`) → 100 (all
  items); twostory 75 → 77 (one alarm item, +15/7 half-up). Client does no math, so the
  app shows exactly these numbers.

## Decisions / surprises

- All promoted to `docs/decisions.md` (placement under Home; server-recompute-per-toggle;
  UserDefaults sidecar for checklist state; request omits findings/constraints/profile;
  `URLSession.shared` in the extension because `session` is file-private).
- Surprise: an S3.4 session was editing `HomeScreen.swift` concurrently (profiles swipe/
  context-menu). Its second `.contextMenu` would have silently replaced the first, so I
  merged Score + Profiles into one leading `.swipeActions` and one `.contextMenu`.
