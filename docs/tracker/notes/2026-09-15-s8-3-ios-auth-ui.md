# S8.3 — iOS: Auth UI

- **Who:** P3
- **Date(s):** 2026-09-15
- **Status when I stopped:** Backend contract fully implemented and tested; the three SwiftUI
  screens are written and type-check but have never been rendered.

## What happened

Built the iOS client for the S8.2 auth endpoints: `AuthClient` (`/auth/register`,
`/auth/login`, `/auth/me`), Keychain token storage, an `AuthSession` state machine, Login and
Signup screens, a root gate, and an Account section in Settings. ~35 commits.

**The shape of the session was decided by one constraint:** this machine cannot run the
simulator, and `FIRST-PRIORITY.md` is open precisely because four bodies of Swift have landed
since 2026-09-09 with no recorded result. Writing S8.3 the conventional way would have made it
a fifth.

So everything that is not a view went into `escape_plan/Auth/` as **pure Foundation**, and that
directory is symlinked into `tools/editorcore` as `Sources/EditorCore/Auth` exactly the way
`Editor/Core` already is. The result is **93 new tests that actually execute here** — EditorCore
went 295 → **388** — covering the whole wire contract, the session state machine, token storage,
error mapping and validation. Only three view files are left unverified instead of all of S8.3.

The cost is a rule that must be respected: **a SwiftUI import anywhere in `Auth/` silently
removes all of that coverage.** It is called out in the directory's header comments, in
`escape_plan/CLAUDE.md`, and in `decisions.md`.

### Grounding the tests in the real backend rather than in my assumptions

Four times I generated fixtures from the actual system instead of writing what I expected:

- **JWTs** signed by `app.auth.tokens.create_access_token` (PyJWT, HS256), including one whose
  payload exercises the base64url `_` alphabet.
- **422 bodies** captured verbatim from `fastapi.testclient`, including the both-fields-wrong
  case, which pins the server's field ordering.
- **Form encoding** round-tripped through Python's `urllib.parse.parse_qsl` — the parser
  Starlette actually uses — for four adversarial inputs.
- **The email rule** cross-checked against the backend's own `normalise_email` over 22
  addresses. All 22 agreed, including the ones that look wrong and are accepted by both
  (`ada@b..co`, `.ada@b.co`).

That last pair caught things I would otherwise have got wrong by reasoning alone.

## Decisions / surprises

All seven are in `docs/decisions.md`. The three worth reading:

**The gate is soft, deliberately.** The brief says "show the Auth flow if no token exists",
which read literally is a wall in front of the whole app. This app is local-first — editor,
routing, drill, export and persistence all work offline — so a wall would put the CAC demo one
Render cold start away from being a login screen, and would need a live account for all 8 UI
tests. "Continue without an account" is a first-class button, and `AuthSheetView` in Settings
lets someone change their mind. Owner-approved during planning.

**I planned a bespoke JSON decoder on a premise that turned out to be false.** The plan said
`.iso8601` cannot parse the fractional seconds pydantic emits. Measured, it parses
`2026-09-16T05:33:58.567000Z` correctly and keeps the 567 ms — and the deployment target is
**iOS 26.5**, so the lenient Foundation parser is guaranteed. I deleted the decoder rather than
keep code justified by a fiction. The *adjacent* trap is real and is what the tests pin instead:
a bare `ISO8601DateFormatter()` returns **nil** for that same string. `.iso8601` and
`ISO8601DateFormatter` are not the same parser, which is very easy to assume.

**`swiftc -typecheck` works on this machine and is worth having.** All **150** files in
`escape_plan/` type-check clean against the iOS 26.5 simulator SDK — in **both** the `-DDEBUG`
and release configurations, exit 0 and 0 errors each (warnings all pre-existing, none in new
code). Run both: the release pass never sees `SettingsScreen`'s `#if DEBUG` Developer section.

```bash
find escape_plan -name '*.swift' > /tmp/srcs.txt
for flag in -DDEBUG ""; do
  xcrun swiftc -typecheck -sdk "$(xcrun --sdk iphonesimulator --show-sdk-path)" \
    -target arm64-apple-ios26.5-simulator -swift-version 5 $flag @/tmp/srcs.txt
done
```

This is **strictly more** than the `swiftc -parse` the FIRST-PRIORITY brief rightly dismisses as
proving nothing — it resolves every type, member and conformance across the module, so
`ARDrillView`, `SemanticMatcher` and the rest genuinely do type-check now. It is **not** a build
(no SIL, no IRGen, no linking) and **not** a test run. I narrowed §0 with it; I did not close it.

Two smaller surprises, both now tested: on iOS a **Keychain item outlives the app that wrote
it**, so a reinstall would silently resume a deleted session (first launch now purges); and
`SecItemAdd` returns `errSecDuplicateItem` rather than overwriting, so the naive add-then-update
order leaves a stale token on every re-login.
