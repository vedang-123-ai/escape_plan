## What happened

Built the editor as two layers, deliberately:

- `escape_plan/Editor/Core/` — pure Foundation, no SceneKit/UIKit, no I/O:
  - `Geometry.swift` — polygon math (CCW/shoelace, self-intersection, edge/t-param resolution,
    point-in-polygon, segment distance).
  - `EditorValidation.swift` — client-side mirror of `backend/app/models.py`'s invariants.
  - `Snapping.swift` — vertex → wall → axis → grid, delta-snapping for translations.
  - `EditAction.swift` — the closed set of mutations + `Selection`.
  - `HomeModelStore.swift` — the single reducer gate.
  - `HitTesting.swift` — what a tap selects (pure, so it's tested) + the needs-review predicate
    S2.2 will render.
- `escape_plan/Editor/SceneKit/SceneKitEditorBridge.swift` — the ONLY device-coupled file.
- `escape_plan/Models/Generated/HomeModel.swift` — schema mirror, marked `replace-with-S0.3`.

The store's guarantee is structural, not a convention: `dispatch` reduces onto a **copy**,
validates it, and only then commits. A rejected action leaves the model bit-for-bit unchanged
and returns the reasons (bridge plays an error haptic).

## Decisions / surprises

All promoted to `docs/decisions.md` (7 rows). The two worth reading here:

1. **No iOS simulator runtime exists on this Mac** — `xcodebuild test` cannot run a single
   test, and `-destination 'generic/platform=iOS'` fails outright ("iOS 26.5 is not
   installed"). Since the acceptance criterion is *"unit tests prove no sequence of store
   actions can produce an invalid model"*, unrunnable tests would have meant no acceptance at
   all. So `tools/editorcore/` is a macOS SwiftPM harness that **symlinks the same source
   files** and runs them with XCTest. No duplicated code. Two runners, one truth:
   - `swift test --package-path tools/editorcore` → 89 tests, ~6s (works here today)
   - `xcodebuild test -scheme escape_plan …` → works on any machine with a simulator
   - app target: `xcodebuild build -project escape_plan.xcodeproj -target escape_plan -sdk iphonesimulator26.5 -configuration Debug CODE_SIGNING_ALLOWED=NO` → **BUILD SUCCEEDED**
2. **I mutation-tested the invariant suite** rather than trusting a green bar: deleting the
   validation gate from `dispatch` turns `StoreInvariantTests` from 0 → **51 failures**, and
   restoring it returns to green. The tests can actually detect the bug they exist to prevent.

Surprise worth flagging: **the schema makes a truly empty home unrepresentable**
(`floors: minItems 1`, `floor.rooms: minItems 1`). The playbook's "starting from an empty
model" therefore starts at one floor + one starter room (`HomeModelStore.newHome()`), and
`addFloor` seeds a starter room for the same reason. If P1/P2 dislike that, the alternative is
a schema change — flagging rather than deciding unilaterally.

## Integration points

**@P2 (S1.3 renderer) — three methods, that's the whole seam.** `SceneKitEditorBridge` talks to
an `EditorSceneAdapter` protocol, not to your node graph. On merge, conform the renderer to:

| Method | Why it's yours | Notes |
|---|---|---|
| `worldPoint(from: CGPoint) -> Point2D?` | You own the camera, so you own the unprojection | Return **floor-local meters** (the schema's frame). `nil` when the ray misses the floor plane. |
| `metersPerPoint() -> Double` | Touch tolerances must scale with zoom | A fixed meter tolerance is unusable at either zoom extreme. |
| `highlight(_ selection: Selection)` | You own the nodes | `.none` clears. Selection is UI state and is never persisted into the document. |

Everything else — what a tap selects, what a drag does, whether it's legal — is already done
and tested; grep `TODO(integration)` for the exact call sites. The two gesture entry points
(`handleTap`, `handleDrag`) just need a `UITapGestureRecognizer` / `UIPanGestureRecognizer` on
your `SCNView`.

**@P2 (S0.3 models):** delete `escape_plan/Models/Generated/HomeModel.swift` wholesale and point
the core at yours. `HomeModelCodableTests` round-trips all 3 fixtures at the **JSON-key** level
(not just Swift-level `Equatable`) — if your models pass that same test file, the swap is a
no-op. Watch the two traps I hit: `from` is a Swift keyword (I used `fromEnd` + CodingKeys),
and `point` is a bare `[x, y]` array, not an object.

**@P1:** `EditorValidation` duplicates `backend/app/models.py`'s invariants in Swift. If you
change a rule there, it has to change here too, or the editor and backend disagree about what
"valid" means. `HomeModelCodableTests.testFixturesAreValidPerTheEditorsOwnRules` is the
tripwire: it asserts the Swift validator accepts every pydantic-valid fixture.

**Nobody has touched `egress`** — it's round-tripped and never authored, per the schema rule.
