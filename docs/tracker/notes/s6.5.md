# S6.5: Conversationally Narrated Household Interview

**Date:** 2026-09-06
**Objective:** Replace the S4.1 demo-seed onboarding with a five-step household interview that produces Profile objects and the schema-2.0 household facts, conversationally narrated, fully skippable, and editable later.

## Implementation Details
1. **API Gap Fix (`score.py` and `main.py`)**: Before modifying the UI, the backend was updated to pass `tornado_plan` and `earthquake_plan` from `main.py` to `compute_score`. This makes the S6.4 severe-weather and earthquake checklist items reachable. A test was added to ensure multi-peril plans produce corresponding safe room and mitigation items.
2. **Onboarding Flow View**: Completely replaced `OnboardingFlowView.swift` with a 5-step wizard (Welcome, Who lives here, Per-person needs, Rent or own, and Finish). The view iterates over a locally managed list of `Person` objects for form binding.
3. **Onboarding State**: Rewrote `OnboardingState.swift` to handle the wizard flow.
    * Uses `seedIfNeeded()` to seed the demo home without explicitly presenting the review or plan steps (so the user has a sandbox to play in right after the flow, maintaining demo ability).
    * `commitAndFinish()` takes the local `Person` answers and dynamically maps them to `Profile`s using `ProfileTag`s: `age <= 12` maps to `.child`, `age >= 65` maps to `.elderly`. Explicit toggles map to `.mobility_limited`, `.hearing_impaired`, and `.vision_impaired`.
    * Creates the `Household` property with `tenure` selection (`.rent` or `.own`) and assigns it to the seeded demo home.
    * Automatically assigns the first available bedroom from the seeded home to the new profiles so they are immediately routable without asking technical questions upfront.
4. **Offline First**: The entire wizard is static copy without any AI dependency or network calls. This guarantees that 502s from AI endpoints will not break the first-launch experience.
5. **No Data Harvesting**: Contextual explanation is given before the "Rent or own" toggle so the user understands why the question is asked.

## Testing
- Backend tests (`test_scoring.py` + `test_checklist_hazards.py`) fully verified the multi-peril wiring gap fix (`pytest backend/tests/ -m "not live"`).
- Xcode project compiled and verified to run the new SwiftUI components correctly.
