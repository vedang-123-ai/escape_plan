## Decisions / surprises

Promoted to `docs/decisions.md`: the hand-rolled exporter (vs Apple's synthesized
Codable), the protocol seam, and the `sequentialRooms` fallback.

**Surprise 1 — no simulator runtime on this machine.** The iOS Simulator *SDK* is
installed but no *runtime* is (`xcrun simctl list runtimes` is empty; the iOS platform
shows as not installed). So XCTest **cannot execute here at all**, and `-destination`
doesn't resolve — `xcodebuild -target … -sdk iphonesimulator26.5 build` is the incantation
that works. This is why the round-trip harness exists as a native `swiftc` binary instead
of an XCTest: it makes the acceptance criterion genuinely checkable rather than
aspirational. `ScanExportTests.swift` compiles but has **never been run** — please run it
if you have a runtime.

**Surprise 2 — `/convert` currently returns schema-INVALID JSON. Not my lane; not fixed
here.** Verified against the live endpoint via TestClient:

```
POST /convert (synthetic-bungalow) → 200 OK
jsonschema: None is not of type 'object' at floors[0].openings[3].egress
```

`app/main.py` declares `response_model=HomeModel` without `response_model_exclude_none=True`,
so the computed-only `egress` field serializes as `"egress": null`, which
`homemodel.schema.json` rejects (it types `egress` as an object, and per `decisions.md`
it should be *absent* until the S1.1 annotator runs). The bug is pre-existing and
independent of S1.4 — it reproduces on the committed fixtures with none of my code in the
path. **@P1: this affects any client validating `/convert` responses against the schema,
including the iOS Codable round-trip test.** Fix is one argument on the route decorator;
I left it alone because the backend lanes merge separately and I didn't want a conflicting
edit from an iOS branch. My harness works around it locally with
`model_dump_json(exclude_none=True)`.

**Surprise 3 — the app had no `NSCameraUsageDescription`.** RoomPlan would have crashed on
first launch on a real device, which would have burned the deferred device step. Added it
(plus `UIFileSharingEnabled` / `LSSupportsOpeningDocumentsInPlace` so scan directories can
be dragged off the device — that's the mechanism for getting fixtures into the repo).
Verified the key lands in the *built* `Info.plist`, not just the pbxproj. This touches
`project.pbxproj`, so expect a merge conflict with other iOS lanes (per the agreed
convention).

**Two bugs I wrote and fixed** (both caught by actually running things, not by reading):
`UInt8(bytes.count &* 37 &+ 11)` traps once the value exceeds 255 — `&*` wraps in `Int`,
not into `UInt8`; and `lazy` is incompatible with the `@Observable` macro (needs
`@ObservationIgnored`).
